# Phase 1 integrity review

Version 2 projects add aligned structured blocks: headline, introduction, paragraph, subheading, image and caption. Each block has one stable ID and English/Norwegian content, with text spans supporting marks and links. Legacy paragraphs remain the current editor projection. Editing a projected text field replaces formatting only in that changed field; untouched block content is retained. Structured editing controls are deferred.

Legacy rows normalize in memory. Reading never writes or migrates the database file. Explicit Save upgrades only the selected article. Unknown schema versions and duplicate IDs are rejected rather than silently overwritten.

Save completion is revision- and session-aware. New edits remain dirty, late completion cannot replace a different open article, and overlapping saves are suppressed. The main process no longer clears dirty state independently. Save As saves a snapshot to a new ID; later edits stay in that copy and remain unsaved. No autosave.

Persistence review: sql.js exports the entire database. Writes now flush a same-directory temporary file, retain the previous database as .bak, then rename. Failed persistence restores the previous in-memory row. A single-instance lock prevents concurrent application writers. Interrupted writes may leave .tmp; it is never automatically loaded. Backups are never automatically substituted for a corrupt primary database. Preserve all files before attempting manual recovery.

Limitations: Windows rename and directory metadata durability still depend on the filesystem and power-loss behavior. The backup is one generation and its copy is not independently atomic. Whole-database export costs grow with library size. This is incremental hardening, not a database-engine migration.

Recommended next decision requiring approval: replace sql.js with a native SQLite driver, transactional writes, WAL and an explicit backup/recovery policy. That introduces native packaging and migration work and was not performed here. Also agree on rich-text editor behavior before exposing structured blocks in the UI. No fetching or AI translation was implemented.

Tests exercise the shared editor state used by React and the real sql.js store in temporary directories. They are not Electron UI automation or power-loss simulations. Run npm test and npm run build.

## Phase 2 implementation review

Readability with jsdom (scripts/resources disabled) runs in an Electron utility process. The renderer receives only typed text spans, marks, HTTP(S) link/image references and block metadata. React renders text without raw HTML. Image references do not initiate network requests in the renderer. The existing version 2 block model is retained. Headline comes from Readability; the first body paragraph is classified as introduction, since that distinction is not reliably standardized on websites. Stable IDs derive from URL, reading-order index and block content; they persist in saved projects, but a changed extraction may produce different IDs.

Short/empty normal extractions trigger a fresh sandboxed Playwright Chromium context with no saved login state. HTTP errors and explicit paywall markers stop extraction. No access-control bypass, cookies import, sign-in or paywall removal is provided. Browser network requests use the same constrained downloader: public HTTP(S), DNS addresses checked and pinned per request, redirect revalidation, GET only, 15-second request deadline, 5 MB response limit. Browser resources have request and byte budgets; images/media/fonts, WebSockets and service workers are blocked. Extraction has a 45-second outer deadline and the utility process is terminated after completion. HTML is decoded as UTF-8; unusual encodings and complex lazy-loading sites may need future support. Readability and incomplete-content heuristics are necessarily imperfect. Review preview before accepting.

The close warning now asks the renderer for its current session state with a request token rather than trusting delayed dirty notifications. A pending save also counts as unsafe to close. Missing renderer replies trigger a conservative warning after two seconds. Accepting extraction uses the same session guard and generation tracking as article switching, and marks accepted content dirty without saving.

Verification: 17 automated tests cover fixtures, reading order, inline sanitization, images/captions, fallback selection, actual Chromium-rendered fixture, invalid/private URLs, acceptance/cancellation, close-state decisions and all existing persistence tests. Production build and Electron launch/utility-process unsafe-URL smoke check pass. Tests do not establish extraction quality on every publisher, simulate power loss, or automate the native close dialog.

Remaining decisions: native SQLite migration/recovery policy remains deferred. Chromium is downloaded separately for development; bundling/updating it for a distributed installer requires a packaging decision. npm audit reports two existing high-severity dependency entries in Electron 39 and its extract-zip dependency; fixing them requires a major Electron upgrade, deferred for explicit review. No AI translation, rich-text controls, regeneration or export is implemented.

## Phase 2 downloader failure correction

Reproduced the supplied Epoch Times URL with the original restricted downloader: ERR_INVALID_IP_ADDRESS (Invalid IP address: undefined). Node autoSelectFamily invokes lookup with all:true, but our custom callback incorrectly returned the single-address signature. The fixed pinned lookup returns the validated address array in all-address mode and the single-address signature otherwise. DNS pinning and private-network checks remain in place. This was a transport failure before Readability received HTML, not evidence that the article required JavaScript.

The same failure was swallowed by browser route.abort(), producing only page.goto net::ERR_FAILED. The production pipeline is now independently importable for tests; worker remains a thin IPC entry point. Errors retain direct-extraction context and underlying navigation/resource details. Browser-install advice appears only for a genuinely missing executable.

The downloader decodes gzip, deflate and Brotli with both wire and decoded 5 MB limits. Browser interception forwards a small header allowlist, preserves response status, content type and Set-Cookie, and removes stale encoding/length headers after decoding. Chromium handles its own fresh-context cookies. Top-level redirects are replayed explicitly because browser redirect chains do not reliably re-enter Playwright routing on every hop; every destination is validated, with a five-hop limit. Non-navigation downloads follow redirects through the constrained downloader. No saved credentials or browser-profile cookies are imported. Unsupported subframe redirects fail conservatively.

Live retest: the supplied URL returned a direct Readability result, 81 blocks, with no fallback needed in this environment. This does not guarantee full publisher content or continued access; geography, publisher restrictions and page changes can produce different results. Paywall/access-control checks remain enabled.

Regression coverage includes Node lookup callback modes and real HTTP fixture-server traffic through the actual downloader and actual production Chromium route handler: gzip, redirect cookies, JavaScript fallback, HTTP 403 diagnostics, decoded-size rejection and private redirect rejection. Only the fixture transport's DNS/socket destination is mapped in tests; production SSRF checks are unmodified. Existing persistence and manual-saving behavior is unchanged.

## Phase 2.1 editor architecture

The main workspace now uses TipTap/ProseMirror for direct structured editing, one editor per language/block. A shared CSS grid row measures to the taller side so variable text lengths do not clip or overlap later aligned blocks. Headline, lead, subheading, body and caption styling comes from block type, not user-controlled pasted HTML. Images occupy a shared row with no empty Norwegian image field. Raster image loading retains the existing isolated downloader.

A shared serializer maps inline spans to/from TipTap JSON without raw HTML persistence. Bold, italic, underline, code and HTTP(S) links survive edits and clipboard paste. Rich edits update the structured block and the legacy paragraph projection together, preventing normalization from overwriting corrections or formatting. English headline edits also update the library/project title. Schema 3 remains unchanged; legacy projects receive an editable headline in the editor view without rewriting their saved data on load. Existing block IDs and translations are retained.

TipTap supplies selection, clipboard handling, keyboard navigation and undo/redo; custom DOM contentEditable handling is not used. History is per block, retained through Save and Save As, and reset when switching article sessions. Enter inserts a line break within the current block; Add aligned paragraph creates a new stable pair. Cross-block structural editing, merging/deleting blocks, image editing and global cross-block undo are intentionally not introduced. Keyboard shortcuts provide basic formatting without a toolbar. Unsupported pasted structures are reduced to the supported inline model, with paragraph boundaries retained as line breaks within that aligned block. Hyperlinks remain editable/formatted but do not navigate the Electron window.

The article URL collapses after acceptance or opening a saved URL project and can be expanded explicitly. The toolbar and library remain accessible while the article scrolls. Saving remains explicit; extraction acceptance, rich edits, paste and undo update the same revision-aware session and close/switch guards. New source edits are authoritative for future translation.

Verification: 31 automated tests pass, including a Chromium UI test exercising English/Norwegian editing, headline/lead changes, formatted HTML clipboard paste, undo/redo, manual save/reopen, cancelled unsaved switching and variable-height alignment. Real sql.js reopen coverage confirms inline marks and links survive storage. The production build passes with non-blocking TipTap use-client and bundle-size warnings. Visual review at 1366x900 confirms readable continuous columns and subtle empty-block placeholders. Per-block TipTap instances may need virtualization for exceptionally large articles; no AI translation or export was added.

## Phase 2.2 editorial fact boxes

Live inspection of the Swedish Epoch Times article found the fact box in a separate DIV inside ARTICLE, immediately after the final body paragraph, with label Fakta generated by a Tailwind before:content class. Readability removes this container. It is not an aside, and the existing parser never sees it. The raw page contains responsive duplicate copies, which are deduplicated by fact content identity.

Editorial groups are captured before Readability using article ancestry plus explicit fact-component signals, or a semantic role=note with heading, prose and citation. An arbitrary aside is not imported. Each source element receives a temporary reading-order marker; captured boxes are replaced by markers during Readability. Missing boxes are reinserted against retained source-order anchors rather than universally prepended/appended. If there are no safe positioning anchors, extraction reports an error. Internal blocks retain label, heading, separate paragraphs, source attribution, inline marks/links and list-item order. Unsupported complex components inside a fact box are retained as text with a review warning. Identifiable unclassified notes produce a warning rather than being silently discarded. Unmarked editorial boxes can still require a future selector/semantic extension.

Schema 4 introduces a factbox group with stable child blocks and optional factRole/listStyle/ordinal metadata. The group has no editable empty text field; its existing children provide paired source/Norwegian TipTap editors. Legacy/schema 2/schema 3 projects normalize in memory; IDs, translations and previous block kinds remain intact. Reads do not rewrite disk data. Save and Save As serialize the full nested group and synchronized leaf paragraph projections.

Preview and editor use restrained shading and borders, preserve group ordering, and render label/title/body/source/list markers distinctly. Capture logic is language-neutral; Swedish label spelling comes from the DOM/CSS class, not an English-language assumption. A narrowly scoped publisher footer filter excludes the observed non-editorial quality-policy panel.

Verification: actual-article fixture in tests/fixtures/swedish-factbox.html retains editorial article markup and text, with scripts/styles/SVG/buttons removed. Source: https://www.epochtimes.se/forberedde-is-dad-i-skolan-de-fortjanar-dodsstraff (retrieved during this task). Regression tests compare every substantive fact paragraph against that DOM, including all charges, dates and source attribution; verify single extraction and position; exercise mid-article semantic notes, lists, sidebar exclusion, translated child edits, SQLite Save/Save As/reopen, older schemas and Chromium preview/editor rendering. Limitations: conservative context/semantic signals may miss differently marked boxes; CSS-generated labels are recognized only in supported literal-content class notation. Complex tables/figures inside fact boxes currently preserve text with a warning rather than full original layout. Nested list entries retain ordering and list style but not indentation depth. ## Phase 2.3 CDATA and entity normalization

Live inspection of the Shen Yun article showed correct Unicode in the visible H1, HTML title and social metadata, but the NewsArticle JSON-LD headline contained a literal CDATA envelope and &rsquo;. Readability selected that structured headline, stripped only outer script-level CDATA wrappers (not wrappers within JSON strings), and left the named entity literal because its internal decoder handles only a small named subset. No browser fallback was needed; the malformed value entered our headline block directly from Readability metadata.

A new extraction-only normalization module uses the entities library for strict, single-pass named/numeric decoding of raw JSON-LD textual fields. Complete non-nested CDATA envelopes are unwrapped using exact delimiters, not broad content-removal regexes. URLs/IDs and other structured properties are not normalized. Parsed DOM text remains under the HTML parser's normal one-pass entity rules. Existing Unicode, literal markup and intentionally double-encoded entity spellings are preserved. Metadata is shielded against Readability's additional basic/numeric entity passes so already-normalized text is not decoded again.

Actual CDATA declarations in HTML markup are located using parser source positions, excluding script strings, attributes, regular comments and escaped examples. Their payload is decoded once and reintroduced as escaped text before extraction. This also preserves angle brackets as literal text rather than interpreting them as formatting. Only pages with these declarations require an additional parse. All normalization occurs before fact-box capture, Readability and block construction. Existing schema 4, stored projects, ID generation, editor, preview, save behavior and guards are unchanged.

Representative fixture tests/fixtures/shenyun-cdata.html contains the actual page metadata and H1 with a short representative body. All 44 tests passed, including complete/partial/nested CDATA, named/numeric references, Unicode/whitespace, literal HTML-like text, intentional entity spellings, every relevant block type, existing Swedish fact boxes, browser/editor behavior and persistence. Production build passed with the existing non-blocking TipTap directive and chunk-size warnings. Live Shen Yun extraction produced exactly Getting Ready for Shen Yun’s 2027 World Tour (24 blocks, direct HTTP). Live English Epoch Times extraction succeeded (50 blocks); live Swedish extraction succeeded (19 top-level blocks, one factbox).

Limits: strict entity decoding of raw structured text requires semicolon-terminated references; ordinary HTML still follows HTML parser rules. Ambiguous embedded or malformed CDATA syntax is left untouched. The publisher's nested CSS produces a non-fatal jsdom stylesheet diagnostic, which does not prevent extraction. This change does not repair previously saved malformed headlines automatically; users can edit them or re-extract explicitly. No translation, export, schema migration or editor changes were introduced.

## Phase 2.6 local article deletion

Saved library entries now have a separate trash-button action, visible on hover, keyboard focus or non-hover devices. The action opens an in-app HTML confirmation dialog naming the article, with Cancel initially focused. It does not use prompt/confirm. When the target is open and dirty, the dialog explicitly warns that its unsaved changes will be discarded. Other current unsaved work is retained. The group has separate open/delete buttons, avoiding nested controls and accidental article switching.

Confirmed deletion uses a narrow trusted projects:delete IPC method and a parameterized row deletion. The store writes through the existing flushed-temporary-file/backup/rename persistence path. A failed write restores the exact raw row and SQLite rowid in memory; the original on-disk database is unchanged. Missing IDs produce an error. Only the selected project row is deleted: no shared image/resource cleanup or database-schema change is performed.

The library removes the successful target immediately and refreshes. If the deleted ID is currently active, the session switches to a fresh empty unsaved-project identity with no content and a clean dirty flag; this new workspace is not saved. Deletion errors stay in the dialog, and refresh failures are distinguished from failed deletes. A synchronous in-flight guard, disabled confirmation/cancel controls and save-in-progress exclusion prevent duplicate deletion and conflicting user saves.

## Phase 2.7 multi-select article library

Library checkboxes and Ctrl+Click toggle article selection independently of the active editor. Shift+Click replaces selection with the contiguous range from the last ordinary/toggle anchor, using current visible sort order. A separate active-row outline and selected-row highlight distinguish open from selected. Ctrl+A and Escape are handled only inside the focused library region (including its rows/checkboxes), so editor text selection is unaffected. A sticky toolbar shows the selected count and Delete selected/Clear actions. Selection is transient and scoped to visible search results; hidden/deleted IDs are pruned instead of being silently included in destructive actions.

Single deletion remains available on every row. Bulk deletion uses one in-app count confirmation and the existing open-dirty-article warning and duplicate-request guard. Successful bulk deletion clears selection through removal of the selected IDs, refreshes the library and resets the editor only if its active ID was included. Cancel/failure retain selection and current work. Save and Save As remain manual and unchanged.

The store prevalidates every requested ID, deduplicates the set, and executes all deletes in one SQLite transaction. Missing IDs and SQL errors abort the entire batch. One flushed-temp-file/rename persistence follows the transaction; a failed disk write restores all original raw rows and rowids within a compensating transaction, preserving unselected rows and the previous on-disk database. There are no per-article best-effort partial successes. The narrow delete-many IPC validates through the store and trusts only the existing main frame. Shared images/resources are never removed. Schema 4 is unchanged.

Verification covers actual Windows Electron Ctrl/Shift-click, checkboxes (including shift ranges), Ctrl+A/Escape, normal opening independent of selection, editor Ctrl+A isolation, cancellation, unsaved-work warning, failed-batch rollback/retry and exact unselected-project persistence after restart. Store regression injects a missing ID, a mid-batch SQLite trigger failure and a disk-write failure; each preserves the complete original set. Existing single-delete, copy/save, extraction and editor tests remain included. Bulk confirmation was visually checked in the real Electron window.

Limitations: selection is not persisted across restarts and is limited to visible filtered rows. Existing no-undo, backup retention, sql.js interrupted-write limits and non-blocking build warnings remain. No translation, export or autosave was added.
